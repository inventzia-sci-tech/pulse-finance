# pulse-finance

Financial events, execution simulation, position accounting, portfolio analytics and exchange
simulation (algo/quant trading) for Pulse.

| | |
|---|---|
| **Repository / package** | `pulse-finance` |
| **Java namespace** | `com.inventzia.pulse.finance` |
| **Python namespace** | `inventzia.pulse.finance` |
| **Depends on** | [`pulse-data`](https://github.com/inventzia/pulse-data) (datum contract, schema generators), [`pulse-beacon`](https://github.com/inventzia/pulse-beacon) (engine, actors, gateways) |

This is the financial domain layer. The event-driven substrate lives in pulse-beacon and the datum
machinery in pulse-data; what is built here is the *financial* content being transitioned from the
legacy `JavaCepFinance` system; see [`initialtransitioning.md`](initialtransitioning.md).

## Package map

### `com.inventzia.pulse.finance.position`: position accounting

The accounting kernel. **Pure**: no engine, no persistence, no clock, and no dependency on
pulse-beacon, so the arithmetic can be proven against fixtures rather than inside a running engine.
All `BigDecimal`; no binary floating point anywhere in a monetary path.

| Type | |
|---|---|
| `PositionTracker` | position, VWAP, realised and unrealised PnL for one instrument. Trades apply atomically: either every field moves or none does |
| `TradeOutcome` | the trade case decomposition made explicit: `OPEN`, `ADD`, `REDUCE`, `CLOSE`, `REVERSE`, `IGNORED_DUPLICATE` |
| `PositionSnapshot` | complete state for persistence and exact restoration, including applied execution ids |
| `Side` | `BUY` / `SELL` |

### `com.inventzia.pulse.finance.schemas`: generated datum types

**Generated, never hand-written** (`./regen.sh`). pulse-finance owns its finance schemas; pulse-data
owns the generators. Every `TYPE_ID` is under `com.inventzia.pulse.finance.`, enforced by
`DatumTypeRegistry` at startup.

| Type | |
|---|---|
| `Position` | published position view: signed size, VWAP, position point |
| `FinanceDatumTypeProvider` | the SPI provider, discovered automatically via `META-INF/services` |

### Planned

| Package | |
|---|---|
| `…finance.position` (additions) | `PositionManagerActor` (the `AbstractActor` rewrite of `MonoStrategyPositionManager`), `PositionAccountingConfig` |
| `…finance.portfolio` | aggregation across instruments, hedge factor, ANV, notional and beta-adjusted delta |
| `…finance.schemas` (additions) | `PositionState`, `PositionCheckpoint`, execution and cash-flow events |
| execution / exchange simulation | not started |

Dependency direction is one way: `portfolio → position`. The accounting layer never reads the
portfolio layer.

## Repository layout

```
schemas/                 finance YAML, owned here (see schemas/README.md)
regen.sh                 regenerates bindings + provider using pulse-data's generators
generator.pin            the one authoritative generator pin: revision + digests
core/java/               pulse-finance-core, the Java module (Java 17)
  src/main/java/...      position/ (kernel) and schemas/ (generated)
  src/main/resources/    META-INF/services, Java-side SPI discovery
src/inventzia/...        generated Python bindings + provider
tests/
  fixtures/              shared cross-language accounting fixtures
  test_*.py              fixture consistency and the installation criterion
docs/                    specifications
scripts/check_versions.py  Maven <-> PEP 440 version consistency
```

## Build and test

The JDK and Maven live in the `pulse` conda env, not on the base `PATH`:

```bash
export JAVA_HOME=~/miniconda3/envs/pulse
export PATH="$JAVA_HOME/bin:$PATH"

mvn -f core/java/pom.xml verify     # Java: kernel against the shared fixtures, plus SPI discovery
python -m pytest tests/ -q          # Python: fixture consistency, installation criterion
python scripts/check_versions.py    # Maven and Python versions must agree
./regen.sh --check                  # committed bindings match the pinned generators
```

`pulse-data` and `pulse-beacon-core` are unpublished snapshots, so `mvn install` them first (CI does
this by checking both out as siblings).

## Schemas are owned here, generated by pulse-data

```bash
./regen.sh            # regenerate bindings and the provider; commit the output
./regen.sh --check    # CI: fail on any drift from the pinned generators
```

Finance owns the *meaning* of its types; pulse-data owns the *machinery* that generates them. A
consuming application installs the package and the types are discovered automatically: Python by
entry point, Java by `ServiceLoader`. Adding a schema is a deliberate, confirmed step: see
[`schemas/README.md`](schemas/README.md).
