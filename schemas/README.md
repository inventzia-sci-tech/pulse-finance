# Finance schemas

Owned here, generated by pulse-data's generators into
`com.inventzia.pulse.finance.schemas` / `inventzia.pulse.finance.schemas` with
`providerId() == "com.inventzia.pulse.finance"`. Run `../regen.sh` after any change, and
commit the generated output. See `../initialtransitioning.md`,
"Decision: datum ownership".

## Committed schemas

| Schema | Type ID | Status |
|---|---|---|
| `position.yaml` | `com.inventzia.pulse.finance.schemas.Position` | v1, confirmed field-by-field against the original `A_MktDatum` |

Departures from the original are recorded on the fields themselves, not here, so they travel
with the contract: `positionVwap` is an exact decimal rather than a `double` (the measured
money defect), `positionPoint` is a string code rather than an enum (a generator limitation,
not a modelling choice), and `publishedTime`/`receivedTime` are dropped in favour of the
engine's run recording, matching the `CdfBar` precedent.

## Still to port

`instrumentId`/`strategyId`/`portfolioId`, currency and decimal scale) and the execution and
cash-flow events the kernel already accounts for. Each is confirmed field-by-field with the
original author before it is written.

Decisions **D1–D5** in `../initialtransitioning.md` still gate anything whose field types they
touch, in particular the instrument/multiplier model (D1) and persisted scale (D2).

## Checklist for each new schema

- [x] Field set confirmed against the original datum, deviations flagged individually.
- [x] Every field checked against `StorageMapping` for exact representability (it refuses
      arrays outright; decimals land on `DECIMAL(38,12)` by default).
- [x] `TYPE_ID` under the provider namespace, so `DatumTypeRegistry` accepts it.
- [x] Entry point in `../pyproject.toml` and the Java `META-INF/services` entry present.
- [x] `./regen.sh --check` green.
- [ ] Clean-environment installation round trip passing (`../tests/test_installation.py`):
      still open; see the release gate.
